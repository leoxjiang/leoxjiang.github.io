# Leo's website maintenance guide

This site is generated by Jekyll and published by GitHub Pages from the `main` branch.

## Recommended publishing flow

1. Create a branch named for the update, such as `content/2026-fall-recap`.
2. Add or edit the relevant Markdown and media files.
3. Build locally and inspect the rendered pages.
4. Open a pull request and review the public content, privacy checklist, and build result.
5. Merge only after approval. GitHub Pages will publish from `main`.

## Local preview

Requirements: Ruby and Bundler.

```sh
bundle install
bundle exec jekyll serve
```

Open the local URL reported by Jekyll. For a release-style check:

```sh
bundle exec jekyll build --trace
```

## Common updates

### Add a news post

Create `_posts/YYYY-MM-DD-short-title.md` with front matter consistent with an existing post. Keep event dates, repertoire, placements, and links factual and source-backed.

### Update the biography

Edit `about.md`. Prefer details that do not expire every school year. Review every sentence for child privacy before publishing.

### Add media

Place files in the matching folder under `images/`. Use meaningful filenames, compress large files, strip metadata, add alt text, and verify publication rights.

### Update navigation or social links

Edit `_config.yml`. These changes can affect every page, so inspect the full navigation before merging.

## Publication checklist

- [ ] Facts, names, dates, repertoire, and results are verified.
- [ ] No school, schedule, address, live-location, identifier, or private contact information is exposed.
- [ ] Photos and documents contain no unintended personal information or location metadata.
- [ ] Media rights are confirmed.
- [ ] Images are reasonably sized and have descriptive alt text.
- [ ] Internal links and media paths work.
- [ ] `bundle exec jekyll build --trace` succeeds.
- [ ] The pull-request diff and rendered pages have been reviewed.
